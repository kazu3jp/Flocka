# アカウント削除

アプリの「自分」→「アカウントを削除」、またはExpo Webの `/delete-account` から開始します。未ログインの場合は同じ画面でログインし、削除画面へ戻ります。Webの公開・ストアへのURL登録は未実施です。

1. Better Authの `POST /api/auth/delete-user` に `callbackURL` を送信します。登録済みアドレスへResendで30分有効の確認リンクを送ります。許可したWebオリジンの `/delete-account` と `flocka://delete-account` のみ受け付けます。
2. リンクを開いても削除しません。同じアカウントでログインし、確認画面で確定すると、同じエンドポイントへ `token` を送信します。Better Authがセッション・対象ユーザー・有効期限を検証します。GETの削除コールバックは拒否します。
3. 削除意図をD1へ保存し、全セッション・本人の通知登録と送信待ち通知を無効にします。Apple/Googleのトークンを失効させ、本人のR2写真を削除します。
4. D1のバッチでプロフィール、バックアップ、設定、交換、送受信した証言、関連する通報・監査、通知と認証データを削除します。相手のサーバー上のバックアップから関連する構造化データを除き、関連する自己PR下書きを解除します。他ユーザーのアカウントは削除しません。古い端末からバックアップを再送しても、保存と同じSQL文内で参照先を照合し、削除済みの交換・証言などを再保存しません。
5. 全処理完了時のみ完了を表示します。写真が500件を超える場合や外部連携の失効に失敗した場合は `ACCOUNT_DELETION_PENDING` を返し、「処理中」と表示します。5分ごとの既存Cronで1回につき最大10件を再試行します。削除中のアカウントへ新しいセッションは発行しません。認証処理の確認と実際の書き込みの間に競合した場合も、DBトリガーでセッション・連携トークンの再登録を拒否します。

`0007_account_deletions.sql` と `0008_deletion_write_guards.sql` が必要です。ローカルはルートで `npm run db:migrate` を実行します。本番のマイグレーション・デプロイは実施していません。

外部トークンは新規保存分をBetter Authの暗号化形式で保存し、既存の平文形式も読み取ります。失効完了は専用列へ記録するため、写真削除の再試行時に失効済みトークンを再利用しません。Apple連携の解除には有効な `APPLE_CLIENT_ID` と `APPLE_CLIENT_SECRET` が必要です。連携アカウントにトークン自体が保存されていない場合は、削除の受付前に該当プロバイダーでの再ログインを求めます。

削除後は、この端末のアカウント別保存データと通知トークンも消去します。他端末にダウンロード済みのデータは次の同期で更新されます。第三者が保存したスクリーンショットや、本人との構造化された関連がない自由記述のコピーを遠隔削除する機能ではありません。

検証は `npm run validate` と `npm run test:vrt`。統合テストは隔離したWorkers/D1/R2で実行し、Resend・Apple・Googleへの外向き通信は捕捉します。実際のメール到着・プロバイダー失効と実機でのリンク起動は別途確認が必要です。
