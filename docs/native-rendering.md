# 実機の描画を確認する（2026-10-20）

実機で報告された重さ・文字欠け・画面切り替え時の配置変化について、次の原因候補を修正しています。端末上で同じ症状を再現し、改善量を測定した結果ではありません。

- カードの光沢移動は、Android/iOSで数値の移動量とNative Driverを使う。Webは原本の百分率指定を維持する。
- 継続するカードの揺れを操作待ちとして扱わない。
- データが変わらない画面移動や通知表示では、デッキの派生データを再計算しない。
- アプリ内の画面ではStackのフェードを外し、表示領域が切り替わる途中の重なりを避ける。
- プレイヤー領域をネイティブの `useLayoutEffect` 内でも計測し、初期の未計測サイズから文字・手札の配置が変化する時間を減らす。後続のサイズ変更は `onLayout` で追従する。
- ネイティブのボタン文字を縮められるレイアウトにし、狭い幅では折り返す。文字サイズの拡大は無効化しない。Webの既存の折り返しは維持する。

## 実機での確認

[USBデバッグ手順](android-device-debugging.md)で同じ端末へ接続し、問題のあった操作を修正前後で比較する。端末の機種、OS、文字サイズ・表示サイズ、アプリのビルド種別、対象画面を記録する。

1. 通常の文字サイズと拡大した文字サイズで、長いボタン、プロフィール名、エラー表示の末尾を確認する。
2. デッキ・カード詳細・交換の画面を往復し、文字や手札が表示後に動かないか確認する。キーボード表示中と閉じた後も確認する。
3. React Native DevToolsのProfilerで同じ操作を記録し、不要な再描画と時間のかかる処理を確認する。
4. 操作の応答時間は開発ビルドと配布用ビルドを区別して記録する。開発時の検査処理があるため、開発ビルドだけから配布時の速度を判断しない。

Webの画像比較と書き出し成功は、ネイティブの文字欠け・フレーム落ちを検証した証拠にはしない。初回修正時は `adb devices -l` に実機が表示されず、端末上のProfiler計測・画面操作は実施していない。

参照: [React Native 0.86のレイアウト計測](https://reactnative.dev/docs/0.86/the-new-architecture/layout-measurements)、[Native Driver](https://reactnative.dev/docs/0.86/animations#using-the-native-driver)、[Flexbox](https://reactnative.dev/docs/0.86/flexbox)、[パフォーマンス](https://reactnative.dev/docs/performance)。

## 再描画と文字欠けの追加修正（2026-10-20）

コードと同梱フォントの計測から特定した原因を修正した。端末上のProfiler計測と、修正前後の目視比較はまだ実施していない。

- **文字欠け（Android）**: RNのTextViewは自身の枠で描画を切り取る。Dela Gothic One / Zen Kaku Gothic Newは ascent 1.16em・descent 0.288em（計1.448em）で、原本CSSの `line-height: 1` などをそのまま使うと、最初の行の上端・最後の行の下端の字形（「」、濁点、g/yなど）が欠ける。`T` はAndroidだけ、不足分を上下のpaddingで描画領域に足し、同じ量の負のmarginでレイアウト上の位置と大きさを保つ。背景・枠線・固定高さを持つ文字は見た目が変わるため対象外。
- **定期同期による全画面の再描画**: 15秒ごとの同期で、内容が同じでも状態・接続相手を新しいオブジェクトに置き換え、`syncing` の切り替えと合わせて表示中の画面を数回描き直していた。内容が同じ場合は既存の参照を保ち、`syncing` とトーストは別のContextへ分けた。Contextの値と操作関数もメモ化した。
- **画面移動ごとの保存**: 画面移動のたびに、写真を含む状態全体をJSON化して端末へ書き込んでいた。状態とナビゲーションを別々に保存する。
- **SVGの再解析**: アイコン・カード絵・ステッカーは画面を開くたびにXMLを解析していた。解析結果をアプリ全体で共有する（`CachedSvgXml`）。ネイティブのSVGはフィルターIDがSVGごとに独立するため固定IDにし、Webは一意のIDを維持する。
- **自己PRの書き出し演出**: 22msごとに画面全体を再描画していた。進捗を小さなストアに移し、本文だけを更新する。
- **封筒の予想画面**: 開封アニメーション中も毎回、状態全体を複製して派生データを再計算していた。状態と予想が変わったときだけ計算する。
