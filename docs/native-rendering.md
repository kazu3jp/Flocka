# 実機の描画を確認する（2026-10-20）

実機で報告された重さ・文字欠け・画面切り替え時の配置変化について、次の原因候補を修正しています。端末上で同じ症状を再現し、改善量を測定した結果ではありません。

- カードの光沢移動は、Android/iOSで数値の移動量とNative Driverを使う。Webは原本の百分率指定を維持する。
- 継続するカードの揺れを操作待ちとして扱わない。
- データが変わらない画面移動や通知表示では、デッキの派生データを再計算しない。
- アプリ内の画面ではStackのフェードを外し、表示領域が切り替わる途中の重なりを避ける。
- プレイヤー領域をネイティブの `useLayoutEffect` 内でも計測し、初期の未計測サイズから文字・手札の配置が変化する時間を減らす。後続のサイズ変更は `onLayout` で追従する。
- ネイティブのボタン文字を縮められるレイアウトにし、狭い幅では折り返す。文字サイズの拡大は無効化しない。Webの既存の折り返しは維持する。

## 実機での確認

[USBデバッグ手順](android-device-debugging.md)で同じ端末へ接続し、問題のあった操作を修正前後で比較する。端末の機種、OS、文字サイズ・表示サイズ、アプリのビルド種別、対象画面を記録する。

1. 通常の文字サイズと拡大した文字サイズで、長いボタン、プロフィール名、エラー表示の末尾を確認する。
2. デッキ・カード詳細・交換の画面を往復し、文字や手札が表示後に動かないか確認する。キーボード表示中と閉じた後も確認する。
3. React Native DevToolsのProfilerで同じ操作を記録し、不要な再描画と時間のかかる処理を確認する。
4. 操作の応答時間は開発ビルドと配布用ビルドを区別して記録する。開発時の検査処理があるため、開発ビルドだけから配布時の速度を判断しない。

Webの画像比較と書き出し成功は、ネイティブの文字欠け・フレーム落ちを検証した証拠にはしない。初回修正時は `adb devices -l` に実機が表示されず、端末上のProfiler計測・画面操作は実施していない。

参照: [React Native 0.86のレイアウト計測](https://reactnative.dev/docs/0.86/the-new-architecture/layout-measurements)、[Native Driver](https://reactnative.dev/docs/0.86/animations#using-the-native-driver)、[Flexbox](https://reactnative.dev/docs/0.86/flexbox)、[パフォーマンス](https://reactnative.dev/docs/performance)。

## 再描画と文字欠けの追加修正（2026-10-20）

コードと同梱フォントの計測から特定した原因を修正した。端末上のProfiler計測と、修正前後の目視比較はまだ実施していない。

- **文字欠け（Android）**: RNのTextViewは自身の枠で描画を切り取る。Dela Gothic One / Zen Kaku Gothic Newは ascent 1.16em・descent 0.288em（計1.448em）で、原本CSSの `line-height: 1` などをそのまま使うと、最初の行の上端・最後の行の下端の字形（「」、濁点、g/yなど）が欠ける。`T` はAndroidだけ、不足分を上下のpaddingで描画領域に足し、同じ量の負のmarginでレイアウト上の位置と大きさを保つ。背景・枠線・固定高さを持つ文字は見た目が変わるため対象外。
- **定期同期による全画面の再描画**: 15秒ごとの同期で、内容が同じでも状態・接続相手を新しいオブジェクトに置き換え、`syncing` の切り替えと合わせて表示中の画面を数回描き直していた。内容が同じ場合は既存の参照を保ち、`syncing` とトーストは別のContextへ分けた。Contextの値と操作関数もメモ化した。
- **画面移動ごとの保存**: 画面移動のたびに、写真を含む状態全体をJSON化して端末へ書き込んでいた。状態とナビゲーションを別々に保存する。
- **SVGの再解析**: アイコン・カード絵・ステッカーは画面を開くたびにXMLを解析していた。解析結果をアプリ全体で共有する（`CachedSvgXml`）。ネイティブのSVGはフィルターIDがSVGごとに独立するため固定IDにし、Webは一意のIDを維持する。
- **自己PRの書き出し演出**: 22msごとに画面全体を再描画していた。進捗を小さなストアに移し、本文だけを更新する。
- **封筒の予想画面**: 開封アニメーション中も毎回、状態全体を複製して派生データを再計算していた。状態と予想が変わったときだけ計算する。

## カード描画とウェルカム演出の負荷削減（2026-10-20）

見た目を変えずに、カード1枚あたりの描画・レイアウト回数とSVG要素数を減らした。端末上のProfiler計測は未実施で、改善量は確認していない。

- **カードの計測**: `StrengthCard` に任意の `height` を追加した。高さが決まっている呼び出し元（カード詳細、デコのプレビュー、プレイヤーカードの手札、見せるカードの選択）は渡し、カード全体の計測と、それによる名前の大きさ・フレーバー文の再計算を省く。渡さない呼び出し元は従来どおり計測する。絵の枠だけを計測し、その大きさを `CardIllustration` と `CardShine` へ渡すため、両者は自身の計測をやめた。
- **SVG要素数**: 放射模様20本、ストライプ、未発見カードの斜線を、それぞれ1つのpathにまとめた。図形同士は重ならないため描画結果は同じ。配色と図形の計算はメモ化した。
- **メモ化**: `StrengthCard`、`CardPattern`、`LockedCard`、`CardIllustration`、`StickerArtwork` をメモ化し、絵の揺れ・光の補間も再利用する。プレイヤーカードの手札も入力が同じ間は同じオブジェクトを使う。
- **見せるカードの選択**: グリッド幅を0から始めず、シート幅（ウィンドウまたはWebのプレビュー枠から左右18pxを引いた値）から始める。実測と異なる場合（Webのスクロールバーなど）だけ実測値で描き直す。
- **文字**: Androidでstyleのない `T` は、フォントと大きさごとに計算した余白を再利用し、styleの平坦化を省く。
- **ウェルカム演出**: ネイティブではNative Driverで動かす。原本の%指定の移動は、要素自身の大きさを計測してpxへ変換する。Webは従来どおりJS Driverと%指定。予想シーンの選択リング（`boxShadow` の補間）はNative Driverで動かせず、不透明度の重ね合わせでは原本の跳ねる動きを再現できないため、JS Driverのまま残した。

プレイヤーカードは、表示領域の大きさが分かるまで手札を描かない作りのため、最初の1回の描画（手札なし）は残る。Webの画像比較（`test:vrt`）はWindowsでは `tools/vrt/build.mjs` の `spawnSync("npm")` が失敗するため実行していない。

## 画面を作り直さないナビゲーション（2026-10-21）

画面の移動はすべて同じ `[page]` ルートへの `router.replace` で行っていたため、戻る操作やタブの切り替えでも、表示する画面を毎回作り直していた（デッキならカード6枚分のSVGとレイアウト計測）。

- ナビゲーションの状態（タブごとのスタック）は、これまでどおりstoreを正とする。画面間の移動では `router.setParams` でURLだけを書き換え、ルートは作り直さない。認証やアカウント削除など `[page]` 以外のルートからは、従来どおり `router.replace` で移動する。
- `features/navigation/ScreenStacks.tsx` は、すべてのタブのスタックにある画面を保持し、表示するのは現在のタブの一番上だけにする。各画面は React 19.2 の `<Activity>` で包む。非表示の画面は状態を保ったまま副作用（カメラ、Bluetooth、ポーリング、カードの揺れ）が止まり、再描画も後回しになる。
- 画面のフォーカスは `components/screen-focus.ts` の `useScreenFocused` / `useScreenFocusEffect` で判定する。ルートが1つなので、expo-routerの `useIsFocused` / `useFocusEffect` では画面を区別できない。戻って再表示した画面は新しい訪問として扱う。
- `Sheet` はModal（別ウィンドウ）のため、非表示の画面ではシートを描かない。画面に戻るとシートも戻る。
- e2eでは、非表示の画面に `testID="hidden-screen"` を付け、`getByText` / `getByTestId` から除外する（`e2e/visual/test.ts`）。`getByRole` は元から非表示の要素を除外する。`persistent-screens.spec.ts` で、戻る・タブ切り替えの後も同じ画面が残っていることを確認する。
- Fabricの非表示処理（`cloneHiddenInstance`）を使うため、ネイティブ端末での表示と、Profilerによる改善量の計測は未実施。

## 動きと余白をそろえる（2026-10-24）

実機で「アニメーションが少ない」「中央ズレや余白の統一が無い」と指摘があり、動きの部品と余白の定数を作った。

- 動きの部品は `apps/mobile/src/components/motion/` に1ファイル1部品で置く。時間とイージングは原本のCSS（`--ease`、`--pop`、0.1秒の押下、`slideUp`、`toastIn`、`flash`）の値で、操作に関わる動きは0.25秒以内。
- 「動きを減らす」は `useReduceMotion`（`AccessibilityInfo.isReduceMotionEnabled` と `reduceMotionChanged`）に一本化した。Webでは同じメディアクエリを最初の描画から同期で読むので、テストは最終状態を即座に見る。ネイティブは起動直後の問い合わせが返るまで動かさない。
- 近くの人と交換の探索表示は `features/exchange/nearby-status.ts`（純粋な状態）から決める。輪（`RadarRipple`）と脈打つ点（`PulseDot`）は、`searching`／`found`（`start()` の完了またはネイティブの `onReady` 後、画面が見えている間）だけ、`transform` と `opacity` をネイティブドライバで `isInteraction: false` のループにする。画面を離れる・探索が止まる・動きを減らすで止まり、12秒の「見つからない」タイマーもその間は破棄する。実機のAndroidでの描画負荷とBluetoothの実際の状態遷移は未検証。
- ネイティブドライバ: 押下、画面・一覧・通知・成功の登場、タブの札、バッジ、進みバーは transform と opacity だけなのでネイティブドライバ。選択肢の色（`SelectionFill`）は色なのでJSドライバで、押下の transform とは別の層に置いて同じノードを共有しない。Webはどれもネイティブドライバが使えないのでJSドライバ。すべて `isInteraction: false` で、入力を待たせない。
- 画面の登場は `ScreenStacks` の画面ごとに `ScreenEntrance` で包み、`useScreenFocused` が false から true に変わった瞬間（と最初の表示）だけ再生する。`Activity` で隠れている画面は動かさず、一覧の登場済みの印は画面ごとに持つので、戻ったりスクロールで戻したりしても再生しない。
- シートの背景は `Modal` の `animationType="slide"` に任せ、別にフェードさせていない（`Modal` を `none` にして自前で動かすと閉じる動きを失うため）。
- 余白は `theme.ts` の `SP`（4pt刻み）と `LAYOUT`（原本の14pt・10/12pt などの名前付き寸法）を使う。レイアウト比較テストが原本の箱と照合するため、原本の寸法は丸めない。
- Webの `RefreshControl` は一覧の `style` をもう一度適用して左右の負の余白を二重にする。引っ張って再読み込みはWebでは動かないので、Webでは付けない。
- Androidで文字が箱の中央に見えるかは未検証（Dela Gothic One / Zen Kaku は ascent 1.16em・descent 0.288em で上下が非対称）。Webでは文字の実インクの中心がボタンの中心から0.5px以内に収まっているのを確認した。

### レイアウトの安定（2026-10-24）

- 入力や押下でほかの要素が動かない決まり: 欄のメッセージは余白に重ね（`FieldMessage`）、操作の結果は押したものの下に出し（`InlineError`）、状態で出入りする文は場所を先に確保する。ボタンの読み込み表示は大きさを変えない。押下は transform だけ。
- キーボード（Android）: `Board` と `Sheet` の `KeyboardAvoidingView` は `behavior="height"` のままにした。React Native 0.86 の `ReactRootView` は `adjustResize` のとき `screenY` に表示領域の下端を渡し、`behavior="height"` は「欄の下端と画面の下端の重なり」だけを引くので、ウィンドウが縮んだ場合は重なりが0になり二重には効かない。縮まない場合（edge-to-edge）は重なり分だけ縮める。縮む場合は、イベントとレイアウトの順で一瞬だけずれうる。実機で未確認。


## カード絵とシールの影（2026-10-21）

原本のカード絵（`drop-shadow(2px 3px 0 ink / .35)`）とシール（`1px 2px 0 / .3`）の影は、SVGの `feDropShadow` で描いていた。react-native-svgはAndroidでフィルターとグループの不透明度をソフトウェアのビットマップへ描くため、カード絵1枚ごとに画面外の描画が発生していた。

- ネイティブでは、絵をインク色で塗った複製を影の量だけずらして下に敷き、その複製を包むViewの不透明度で薄める（`components/drop-shadow-svg.tsx`）。`needsOffscreenAlphaCompositing` により、AndroidはGPUのレイヤー、iOSはグループ不透明度で合成されるため、図形の重なりが濃くならない。ずらす量はフィルターと同じSVG座標系で指定する。
- Webは基準画像と一致させるため、従来どおり `feDropShadow` を使う。
- Chromiumで全33素材（カード絵21、シール12）を描き比べ、フィルターと今回の方式の差が最大1ピクセル（160×160の描画内）であることを確認した。ネイティブ端末での描画と速度の計測は未実施。
