# AIによる自己PRの下書き

自己PR画面の「AIで文章を整える」は、Cloudflare Workers AIで下書きを作ります。利用者が押したときだけ動き、確認画面で「この下書きを使う」を選ぶまで何も保存しません。

下書きは「」の引用もカード名も使わない、そのまま読める文章です。そのかわり、各文が仲間の証言だけに基づいていることを、サーバーが3段階で確かめます（文ごとの出典、語の照合、Clefによる意味の判定。[出力の検証](#出力の検証と限界)）。どれか1つでも通らなければ返しません。

2026-10-30に実際のWorkers AIで、gemma-4による生成からClefの判定・書き直しまでの流れを確かめました（[実測](#実測2026-10-30実際のworkers-ai)）。

## 流れ

1. アプリが `POST /v1/me/pr-draft/ai` へ強みのキーだけを送る。
2. サーバーがD1から**本人の**証言を読む（開封済み・非表示でない・削除されていない・どちらの方向のブロックもない・2人以上の別の贈り手）。アプリが送った文面は使わない。
3. 生成とClefの利用枠を、1回の原子的な予約でまとめて取る。
4. gemmaに、文ごとに根拠の証言番号を付けたJSON（`{"claims":[{"sentence","sourceIndexes"}]}`）を書かせ、機械的に検証する。
5. 検証を通ったら、Clef（`@cf/cloudflare/clef`）に各文が根拠の証言で裏づけられているかを判定させる。
6. 4か5で落ちたら、落ちた理由（根拠のない語、裏づけられない文など）を添えて**1回だけ**書き直させ、もう一度4と5を行う。書き直しの利用枠は別に予約し、利用者の1日の回数は増やさない。
7. 通った場合だけ `{ text, source, model, generatedAt }` を返す。`source.pieceIds` は**実際に根拠にした証言だけ**で、既存の `prDraftSource` と同じ形なので、採用時に保存するとサーバーの出典検証（`PR_SOURCE_UNAVAILABLE`）を通る。
8. 採用すると、下書き・出典に加えて `prDraftOrigin: { kind: "ai", model, generatedAt }` を保存する。手で直してもAIが作った文章だという記録は残り、画面の注記もそれに合わせて変わる。「もう一度書き出す」で消える。

締切（25秒）は、生成・Clef・書き直し・予備の依頼をすべて含めて共有します（アプリ側の待ち時間は35秒）。

対応コード: `apps/api/src/routes/pr-ai.ts`、`services/pr-ai-generation.ts`、`services/workers-ai.ts`、`repositories/pr-ai-evidence.ts`、`repositories/ai-usage.ts`。プロンプト・出力検証・Neuron計算は `packages/domain/src/pr-ai-*.ts` と `ai-neurons.ts` の純粋関数です。

## モデルとNeuronの計算

無料枠はアカウント全体で1日10,000 Neuron（UTC 0時 = 日本時間9時にリセット）。無料プランで超えると呼び出しがエラーになり、課金はされません。

既定は `@cf/google/gemma-4-26b-a4b-it`（入力 約9,091 / 出力 約27,273 Neuron per 100万トークン、コンテキスト256k）。

### 実測（2026-10-24、架空の証言3セット、実際のWorkers AI）

この実測は、「」で引用させていた旧い方式（Clefなし）で行ったものです。モデルの選定と推論の扱いの根拠として残しています。

| モデル                          | 結果                                                                                                                                                                                                              |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@cf/google/gemma-4-26b-a4b-it` | 良好。`enable_thinking: false` を付けると、プロンプト約340〜450・出力約30〜100トークン、**1回あたり約5〜6 Neuron**、1〜10秒。3セットとも検証を通り、指示文を含む証言（「以前の指示を無視して…」）には従わなかった |
| `@cf/qwen/qwen3-30b-a3b-fp8`    | 不可。同じ `chat_template_kwargs` を付けても本文が空（推論だけで出力が尽きる）                                                                                                                                    |
| `@cf/zai-org/glm-4.7-flash`     | gemmaより弱い。「一字一句の引用」の指示を2回守らず、1回は証言に混ぜた指示文そのものを証言のように引用した                                                                                                         |

確認した事実:

- gemma-4は**既定で推論（thinking）が有効**です。何も付けないと `completion_tokens` が上限に達し、本文が空で推論だけが返りました（`finish_reason: "length"`）。
- リクエストに `chat_template_kwargs: { enable_thinking: false }` を付けると本文が返ります。これは `packages/domain/src/ai-neurons.ts` の `MODEL_REQUEST_EXTRAS`（モデルごとの追加フィールドの表）に1か所だけ置き、サーバー（`buildPRAiRequest`）と評価ツールが同じ表を使います。実測で確認していないモデルには何も付けません。
- 応答の `usage` に Cloudflare 自身が計算した `neurons` が入ります。サーバーはこれを実コストとして使い、無ければ `トークン数 × 単価表`、それも無ければ予約額（上限値）を使います。
- 応答の `model` は `@cf/google/gemma-4-26b-a4b-it-external` でした。

単価表（参考値。1,500入力+700出力トークンの場合。実際の1回は上記のとおり約5〜6 Neuron）:

| モデル                                     | 入力   | 出力    | 1,500入力+700出力 |
| ------------------------------------------ | ------ | ------- | ----------------- |
| `@cf/google/gemma-4-26b-a4b-it`（既定）    | 9,091  | 27,273  | 約32.7            |
| `@cf/qwen/qwen3-30b-a3b-fp8`               | 4,625  | 30,475  | 約28.3            |
| `@cf/zai-org/glm-4.7-flash`                | 5,500  | 36,400  | 約33.7            |
| `@cf/meta/llama-3.3-70b-instruct-fp8-fast` | 26,668 | 204,805 | 約183             |

表は `ai-neurons.ts` の1か所だけにあり、表にないモデルは最も高いモデルの単価で見積もります。

回数の目安: 1回約5〜6 Neuronなので、無料枠全体で1日約1,700回、ソフト上限9,000では約1,500〜1,800回です。1人あたりは1日5回なので、利用者数がこれを超えない限り全体の予算には届きません。予約は上限値（プロンプトの文字数×1.2トークン + 600出力トークン、約25 Neuron）で行い、呼び出し後に実コストへ置き換えます。同時に予約中の件数が多いと一時的に予算が足りなく見えますが、精算で戻ります。

### 実測（2026-10-30、実際のWorkers AI）

`wrangler dev` の一時Workerから本物の `AI` バインディングで、サーバーと同じ関数（`buildPRAiMessages`・`validatePRAiOutput`・`buildPRAiGroundingRequest`・`parsePRAiGroundingDecision`・`buildPRAiRepairMessages`・`runHedged`）を実行しました（D1と利用枠は通していません）。評価ツールの3セットを各6回使っています。

| 確認 | 結果 |
| --- | --- |
| 現在の方式（引用なし・カード名なし） | 18回中17回が合格（13回は書き直し後）。全体の所要時間は中央値4.1秒・最大6.8秒。生成は中央値1.7秒、Clefは中央値0.5秒 |
| 拒否の内訳 | 証言にない語（「姿勢」「大切」「周囲」「共有」など）9回、Clefによる拒否6回 |
| Clefの値（同じ入力で3回とも同値） | 証言を言い換えただけの文は0.60〜0.79、役職・受賞・期間・心がけを足した文は0.01〜0.16。しきい値は0.5 |
| 応答時間（gemma単体） | 1回目の生成は23回で中央値1.5秒・最大4.3秒。書き直しは15回で中央値2.0秒、5.3・5.6・9.9・11.4・43.1秒の遅れがあった。内部エラー `8005` は40回中2回で、0.7秒・2.3秒で返った |
| 予備の依頼 | 予備を0.8秒で送る設定にした8回では、8回とも2本を同時に送り、先に返った答えを使った |

この測定で見つかり、直した問題:

- Clefの応答は `{"type":"noul","noul":0.86}` の形で、数値だけを期待していた読み取りでは常に判定不能（-1）になっていた。
- しきい値0.9では、証言どおりの文（0.60〜0.79）も落ちていた。
- gemmaは文中に `[1]` のような証言番号を書くことがあり、「証言にない数字」として拒否されていた。番号は出典の目印なので、検証の前に取り除く。
- 「〜してくれた」は仲間から見た言い方で、本人の自己PRでは誰かにしてもらった話に読める。拒否して書き直させる。

## 制限

| 項目                   | 値                                                | 定義                                               |
| ---------------------- | ------------------------------------------------- | -------------------------------------------------- |
| 1人あたり              | 1日5回（UTC日）                                   | `PR_AI_DAILY_CALLS_PER_ACCOUNT`                    |
| 全体のソフト上限       | 1日9,000 Neuron                                   | `PR_AI_DAILY_NEURON_BUDGET`                        |
| モデル待ち時間         | 25秒（生成・Clef・書き直し・予備の依頼をすべて含む） | `AI_DEADLINE_MS`                                   |
| 予備の依頼             | 6秒（締切の24%）答えが無ければ1本だけ送る         | `HEDGE_AFTER_DEADLINE_SHARE`                       |
| クライアントの待ち時間 | 35秒                                              | api-clientの `PR_AI_TIMEOUT_MS`                    |
| 出力                   | プロンプトは250字以内、検証の上限500字            | `PR_AI_MAX_CHARACTERS`                             |

予約は呼び出し前に行います。D1の1回のバッチで、全体の予算と1人あたりの回数を条件付きUPDATEで同時に確認するため、並行リクエストが上限を超えることはありません（`tests/pr-ai.integration.test.ts` の並行テスト）。予約額は「プロンプトの文字数×1.2トークン + 600出力トークン」の上限値で、呼び出し後に Cloudflare の `usage.neurons`（無ければトークン数×単価）で置き換えます。どちらも無い応答では予約額（上限値）をそのまま使います。

使用量はD1の `ai_usage_days`（日ごとのNeuron合計・回数）と `ai_usage_accounts`（日ごとの1人あたり回数）に保存し、cronの `maintenance.ai_usage` が7日より古い行を削除します。アカウント削除時は `accounts` からカスケード削除されます。

## 失敗時の動作

失敗を成功として扱わず、偽のAI結果も返しません。いずれの場合も既存の下書きは変わりません。

| 状況                                                                                                                                                            | 応答                        | 枠の扱い                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------ |
| 1人あたりの上限                                                                                                                                                 | 429 `AI_LIMIT_REACHED`      | -                                                            |
| 全体の予算超過、またはCloudflareの日次枠エラー（4006・neurons）                                                                                                 | 429 `AI_BUDGET_EXHAUSTED`   | 4006の場合は当日分を満額にし、以後はAIを呼ばない。回数は戻す |
| Workers AIの一時的なエラー（`8005`・`3043` の内部エラー、`3040` の混雑） | もう1本の依頼で答えが返れば続行。2本とも失敗なら 502 `AI_UNAVAILABLE` | 成功時は失敗した依頼のNeuronを戻す。失敗時は回数もNeuronも戻す |
| その他のAIエラー（モデルが無いなど。やり直しても同じため2本目は送らない） | 502 `AI_UNAVAILABLE`        | 回数もNeuronも戻す                                           |
| 締切までに答えが無い                                                     | 502 `AI_UNAVAILABLE`        | 回数は戻すが、課金されている可能性があるためNeuronは残す     |
| 生成は通ったがClefの呼び出しが失敗                                       | 502 `AI_UNAVAILABLE`（「AIの根拠を確認できませんでした」） | 生成の分は実コストで残し、回数は使ったものとする |
| 検証かClefで落ち、1回の書き直しでも通らない。推論で出力が尽きて本文が空（`finish_reason: "length"`）の場合を含む | 502 `AI_OUTPUT_REJECTED`    | 呼び出した分を実コストで精算して残す。利用者の回数は1回だけ |
| 書き直しの時間（締切の5分の1）・予算が残っていない、または書き直しの呼び出し自体が失敗 | 502 `AI_OUTPUT_REJECTED`（最初の下書きが拒否されたため） | 書き直しの分だけ戻す（答えが無かった依頼のNeuronは残す） |
| 強みが未確認・ブロックで2人未満                                                                                                                                 | 409 `PR_CARD_NOT_CONFIRMED` | 予約しない                                                   |

メッセージにはUTC 0時（日本時間の朝9時）にリセットされることを含めます。証言の文面はログに出しません（件数・モデル・Neuron・拒否理由だけ）。

## 遅延と一時的なエラーへの対処

Workers AIは、まれに応答が大きく遅れたり（測定では最大43.1秒）、内部エラー（`8005`、約5%）を返したりします。どちらもこちらでは直せないため、サーバーは生成・Clefの呼び出しそれぞれにつき**同じ依頼をもう1本だけ**送れるようにしています（`apps/api/src/services/workers-ai.ts` の `runHedged`）。

- **遅いとき**: 6秒たっても答えが無ければ2本目を送り、先に返った答えを使います。測定では1回目の生成は最大4.3秒だったため、普段は送られません。
- **一時的なエラーのとき**: すぐに2本目を送ります。上限超え（`4006`）や、モデルが無いなどのやり直しても同じエラーでは送りません。
- 2本目を送るのは、締切の5分の1以上が残っていて、全体の利用枠に予約できたときだけです。利用者の1日の回数は増やしません。
- 答えが返った依頼は実コストで精算し、失敗した依頼は課金されないので戻し、答えを使わなかった依頼は課金されている可能性があるため予約額（上限）のまま残します。
- Workers AI全体が混んでいて2本とも遅い・失敗するときは、正直に `AI_UNAVAILABLE` を返します。別のモデルへ切り替えることはしません。

## 出力の検証と限界

証言は他の利用者が書くため、プロンプトでは番号つきの `<testimony>` を `<testimonies>` で囲んだ「データ」として渡し、命令に従わないことを指示します。プロンプトは守られるとは限らないので、サーバーが次の3段階で確かめ、どれか1つでも通らなければ捨てます。

**1. 構造**（`validatePRAiOutput`、`packages/domain/src/pr-ai-output.ts`）

| 検査 | 拒否理由 |
| --- | --- |
| 推論ブロックを除いて空でない | `empty` |
| `{"claims":[{"sentence","sourceIndexes"}]}` の形で、文は1〜4件、各文に1件以上の証言番号、全体で2件以上の別々の証言 | `invalid-structure` |
| 証言番号がサーバーの読んだ証言を指す | `unknown-source` |
| 合わせて500字以内 | `too-long` |

**2. 語の照合**（各文を、その文が根拠にした証言とだけ照合する）

| 検査 | 拒否理由 |
| --- | --- |
| 「」『』で引用していない | `quotation-marks` |
| URL・Markdown・HTMLがない | `forbidden-format` |
| 「〜してくれた」（仲間から見た言い方）を使っていない | `giver-perspective` |
| カードの名前をそのまま書いていない（贈り手がその言葉を書いていれば可） | `names-strength` |
| 数字がすべて根拠の証言にある。文中の `[1]` のような証言番号は先に取り除く | `fabricated-number` |
| 2文字以上の漢字・カタカナ・英字の語が、すべて根拠の証言か、つなぎの語（`PR_AI_NEUTRAL_TERMS`: 自己PR、仲間、言葉、強み、証言、評価、声）にある | `unsupported-term` |

**3. 意味の判定**: Clefに、各文とその根拠の証言を渡し、「証言にない事実・評価・意図・結論を足していないか」を判定させます（言い換えは可）。すべての文が0.5以上でなければ拒否します。

拒否したときは、理由と根拠のなかった語・裏づけられない文をそのまま書き直しの指示に使います（`buildPRAiRepairMessages`）。ログには理由とClefの値だけを出し、文面は出しません。

**出典の決め方**: 各文の `sourceIndexes` から、実際に根拠にした証言だけを `source.pieceIds` にします。読み込んだが使わなかった証言は出典に入れません。

**限界**:

- 1文字の漢字（「心」「高」など）と、ひらがなだけの語は語の照合では見ません。「心がけました」「とても」のような付け足しは、Clefが見落とすと通ることがあります（実測でも「心がけました」が1回通りました）。
- Clefの判定は確率で、しきい値0.5は3セットの実測から決めた値です。証言の書き方によっては、正しい言い換えが落ちたり、軽い言い過ぎが通ったりします。
- 引用をやめたため、文が証言と一字一句同じであることは保証しません。保証するのは、使う語が証言にあることと、Clefが意味の上で裏づけられると判定したことです。

そのため確認画面に「AIが仲間の言葉をもとに書いた下書きです。仲間の言葉に沿っているかを自動で確かめていますが、使う前に読んで確認してください」と根拠にした人数を表示し、採用前に利用者が読む前提です。

## 評価ツール

```
CLOUDFLARE_ACCOUNT_ID=... CLOUDFLARE_API_TOKEN=... npm run eval:pr-ai
npm run eval:pr-ai -- --models @cf/google/gemma-4-26b-a4b-it,@cf/qwen/qwen3-30b-a3b-fp8
npm run eval:pr-ai -- --dry-run
```

3つの架空の証言セット（指示文を含むものを1つ含む）を、サーバーと同じプロンプト・構造と語の検証・Neuron表で各モデルに通し、出力・検証結果・トークン数・推定Neuron・遅延・推論の有無を表示します。Clefの判定と書き直しは行いません（上の実測は、それらを含めた一時Workerで行いました）。環境変数が無いと、その旨を表示して実行しません。`--dry-run` はプロンプトだけを表示します。トークンは保存しません。評価の呼び出しも無料枠を消費します。

## モデルの切り替え

`apps/api/wrangler.jsonc` の `vars.PR_AI_MODEL` を変えてデプロイします。単価表に無いモデルは高単価で見積もられるため、先に `ai-neurons.ts` の表へ追加してください。出力形式が異なるモデルは `eval:pr-ai` で検証を通ることを確認します。

## 本番に出す前の条件

- マイグレーション `0011_ai_usage.sql` を本番D1へ**デプロイより先に**適用する（未適用だとこのエンドポイントは500になります。他の機能には影響しません）。
- アカウントでWorkers AIが利用でき、`wrangler.jsonc` の `ai` バインディング（`AI`）が有効であること。
- 本番のデプロイ・マイグレーションは、このリポジトリのルールに従い明示的な依頼があるときだけ実行します。

## プライバシー

証言の文面（最大3件）と強みの名称がCloudflare Workers AIへ送られます（生成のgemmaと、判定のClef）。メールアドレス・名前・写真・贈り手のIDは送りません。Cloudflareのデータ利用ページ（https://developers.cloudflare.com/workers-ai/platform/data-usage/）は「Cloudflare does not use Customer Content processed by Workers AI to train AI models.」と記載し、標準の推論リクエストでは入出力を必要がなくなった後に保持しないとしています（例外あり）。この記載は2026-10-24に確認したものです。

`packages/domain/src/legal.ts` のプライバシーポリシーに「AIによる下書きの作成（任意）」を追記しました。**運営者は文面を確認してください。** `LEGAL_VERSION` と更新日（2026-10-14）は変更していません。同意の確認は登録時の1回だけで（`/me/terms` は現在のバージョンと完全一致を要求）、既存利用者へ再同意を求める仕組みがないため、バージョンを上げると配布済みの旧アプリの登録が失敗します。文面を正式に改定する日付・バージョンの扱いは運営者が決めてください。
